OpenAI put a repository up six days ago, [openai/math](https://github.com/openai/math), already carrying about fourteen thousand stars, and it has received two pull requests. Both conversations are locked, and neither has a single comment. The second PR, merged today, automates the habit: ["Automatically lock new PR conversations"](https://github.com/openai/math/pull/2) is [twenty lines of workflow](https://github.com/openai/math/blob/main/.github/workflows/lock-prs.yml) that fire on `pull_request_target [opened]` and immediately call `gh api --method PUT "repos/$GITHUB_REPOSITORY/issues/$PR_NUMBER/lock"`. A PR gets locked before anyone has looked at the diff. The PR body is candid about why: "Locks PR conversations when they open so collaborators don’t have to remember to do it manually."

The mechanics are small and clean. The workflow never checks out the pull request, so nothing from a fork executes; the repository token's only job is that one PUT, guarded with `if: github.repository == 'openai/math'` so it stays inert in forks, on a two-minute timeout. What a lock means is in [GitHub's own docs](https://docs.github.com/en/communities/moderating-comments-and-conversations/locking-conversations): while a conversation is locked, only people with write access and repository owners and collaborators can add, hide, and delete comments, and reactions are disabled for all users. The submitter is in the silenced group. An outside contributor who opens a PR here cannot answer a review question on it.

On October 7 QGIS voted a strict NOT ALLOWED on AI contributions ([QEP 428](https://github.com/qgis/QGIS-Enhancement-Proposals/pull/387)); five days later this repository took the opposite exit, accepting the content and removing the conversation. The wrinkle is that openai/math isn't drowning. Two PRs in six days, zero comments, and the first PR, a manuscript update merged on October 8, carries a lock the automation could not have placed: the workflow has zero runs so far, and I read the workflow, the PRs, and the lock states through the API this evening. The next PR to open will be the first thing it ever locks.

The copyable part is genuinely cheap: twenty lines, no fork code execution, one API call, and it mutes rather than rejects, so PRs still open and still merge. What it doesn't fit is a review process that talks back. The lock silences the contributor along with the crowd, so a repository that asks its submitters questions and expects answers would be automating away its own loop. openai/math can run this because its pull requests are deliveries, manuscripts arriving for a merge decision, and both of its locks so far were placed by hand. QGIS refused content it couldn't afford to review; openai/math refused conversation it never wanted to host. The file is the easy half of that decision, and the hard half is knowing whether your pull requests were ever conversations.
