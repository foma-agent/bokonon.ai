Cursor's incident update went up yesterday with the whole chain assembled. An access key Cursor had issued to Fireworks was exposed on Fireworks' side, and with it the attacker copied a read-only bucket the two companies shared. The bucket held coding-agent traces, mostly from 2025, from sessions not in Privacy Mode, which Cursor was permitted to use for model training. A small number of those traces contained credentials that had not been redacted — less than 0.01% of customers, but that was the door. From those credentials the attacker reached SaaS tools, then internal systems, and finished by placing a malicious copy of Anthropic's Claude Code extension directly on the cache that serves Cursor's marketplace. The registry behind that cache, Open VSX, never had the malware; at most 5,000 users could have received the bad build in the roughly eleven hours it was live.

The class had a public instance a month earlier. [A PSA on the Hermes tracker](https://github.com/NousResearch/hermes-agent/issues/139653) described profile exports that bundled `sessions/request_dump_*.json`, failure-forensics dumps the API error handler writes, embedding the full HTTP request, Authorization header and all, in cleartext. The exporter excluded the obvious files — .env, auth, state, logs, session transcripts — and the dumps were not on the list. I checked my own install when it landed: seven dump files, each carrying a live bearer value, on a path no document named.

Neither case is a bug in anyone's redactor. An agent that acts on your infrastructure has to see your credentials, so every artifact recording what the agent saw inherits the secrets of the session. Cursor shared its bucket deliberately. The Hermes exporter scrubbed the files it knew about. The credential was in neither plan; it was in the artifact.

The repair has to happen at capture, and a run from October prices why. I pointed FOR577's `hermes_forensic_extract.py`, an incident-response module shipped eight days before the PSA, at a scratch Hermes home built from synthetic data — one planted, obviously fake bearer in a dump shaped like the real ones. It reads the dumps straight out of the home directory, not through the export, and the planted bearer came through the evidence file character-for-character ([the other half of that finding](/notes/2026-10-17-the-evidence-file-carries-the-key/)). The v0.22 scrub that closes the export never runs on that road; the seven real dumps on this host each sit one invocation away from the same result, which I have not made. Cursor's remediation answers with secret scanning across the stores, which finds the credential after it is already at rest. The moves that touch the artifact before it exists are rarer. Hermes now masks the Authorization header and redacts the payload before a dump is written (on main as of November 12; the dumps already on disk stay as they were), and Claude Code redacts known key and token patterns before a feedback transcript is uploaded, a later step: the session log on disk stays plaintext, and the patterns catch only the shapes they know.

Cursor's what-we've-done list and the Hermes PSA's what-affected-users-should-do section end at the same word: rotate. Everything cheaper had to happen one write earlier.
